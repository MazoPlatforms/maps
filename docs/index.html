Project documentation

A map is a beginning.

Mazo Maps is an open-source mapping project by Mazo Platforms, Inc. These notes describe the Sri Lanka Overture extract, its build pipeline and the data limitations.

Current experience

The website renders a MapLibre map of Sri Lanka. GitHub Actions resolves the latest official Overture release and builds regional PMTiles for the requested bounding box. The regional extract is not a service boundary, a completeness guarantee or a claim of Google Maps-equivalent coverage. Label glyphs use a public external font endpoint; the map needs an internet connection.

No project-owned POIs, routing service or live traffic is included. No API key is embedded in the site.

Architecture

The static site separates presentation, map configuration and data-source registration. The Actions workflow uses the official Overture regional tile pipeline, validates source coverage and PMTiles metadata, then publishes the site if it fits GitHub Pages limits. 

index.html                 Landing page
assets/css/site.css        Responsive layout and themes
assets/js/app.js           Theme controls and map initialization
assets/js/config.js        Sri Lanka bounds and style registry
assets/styles/             Light/dark vector styles
data/sri-lanka/            Generated PMTiles and build manifest
scripts/                   Build validation and live smoke checks

Data provenance

The map uses Overture Maps data and includes OpenStreetMap-derived content. The workflow records the Overture release, tile-builder image digest, filtered source row counts, available vector layers and per-archive SHA-256 values in its generated manifest.

Counts describe source rows selected by the bbox filter, before tile deduplication. They do not prove complete coverage. Place and road labels are rendered only where source names are available. No geographic features are invented to fill gaps.

Run and contribute

Serve the repository root with any static HTTP server. The archives are produced by the GitHub Actions workflow and are not committed as generated binaries. Contributions should retain source attribution, regional limits and reproducible provenance.
