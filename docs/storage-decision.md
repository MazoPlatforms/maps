# Canonical physical storage decision

Selected for the bounded integrated release: transactional SQLite as an indexed working database; full-record, immutable, content-addressed gzip JSONL shards plus a manifest and sharded full revision history as durable Git-reviewable snapshots. A snapshot contains every imported feature, not only edits. Production reads and builds use these Mazo-controlled records and need no Overture access.

The original logical path `data/sri-lanka/{province}/{district}/{ds-division}/{feature-type}/{feature-id}.json` remains available through `scripts/dataset.py export-json`; the unchanged Phase 1.5 physical file pilot and its tests remain supported. The new snapshot uses `data/canonical/records-{id-prefix}.{sha256}.jsonl.gz` with a UUID index in SQLite. Geographic memberships are indexed separately. Cross-boundary features have one ID/geometry. The physical format is deliberately different from one file per feature, for the measured reasons in `canonical-benchmark.md` (42.6 GB minimum block estimate, scan costs and Pages limits).

Records are sorted by permanent ID. Prefix buckets split recursively if their uncompressed data exceed 2 MiB. Histories use the same strategy and retain full revisions, prior hashes, source provenance and tombstones. Hashes address compressed bytes; gzip timestamps are zero. Ordinary edits change only affected record/history buckets. A single-feature history larger than 16 MiB fails rather than growing without bound. SQLite updates are transactional and indexed; export and compiler memory are still bounded-pilot implementations, not verified nationwide streaming engines.

The manifest is the snapshot commit point. Immutable blobs allow known-good snapshot rollback. Git contains reviewed changesets and a bounded independently owned baseline; applying the transaction journal materializes complete canonical current records. Compiled PMTiles, static APIs, search and routing are separate generated outputs. Neither source snapshots nor accepted edits depend on permanent Overture suppression layers. The old national public viewer remains a compatibility mode until a complete canonical dataset is ready.

Changesets carry the dataset version and expected original feature hashes. New features have random UUIDs; updates preserve ID/type/origin; deletion creates a retained tombstone. Administrative memberships are recomputed against the pinned authoritative classifier. New features, direct fork contributions and browser handoff files use the same changeset schema and transaction validator. Boundary corrections are reported for elevated human review and do not mutate the classifier automatically.

This session's import is bounded to 13,993 original source records: 1,995 places, 9,997 buildings, 2,000 roads and the authoritative Colombo DS boundary (LK1103). Eight rejected source records remain in `quarantine.json.gz`, with their original geometry/provenance and rejection reasons. No inferred or synthetic geography is published. Original raw sample files remain outside Git; immutable canonical records, full original properties and provenance are committed. Source-specific notice review remains required before a production geographic release.

National storage requires a Mazo-controlled durable object store or database backup service and a streaming importer/compiler with restoration and incremental-build benchmarks. No such service has been provisioned. The CLI validates at most 20,000 records per release here; national conversion is blocked. This is a physical design decision with working regional implementation, not evidence of national capacity or production deployment.
