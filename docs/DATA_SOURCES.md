# Data sources and provenance

## Sri Lanka basemap

- **Geographic data:** latest official Overture Maps release resolved by the GitHub Actions build from the Overture STAC catalog.
- **Area:** bbox `[79.3, 5.8, 82.1, 10.1]`, selecting source features whose bounding boxes intersect the requested extent.
- **Themes:** base (land, land cover, land use, water and available supporting layers), transportation (segments and connectors), buildings (buildings and building parts when available), and places (with names where provided by the source).
- **Format and hosting:** four PMTiles archives generated by Overture's published tile pipeline, hosted with the site on GitHub Pages. The actual release, feature row counts, named-row counts, layer list, image digest, archive sizes and hashes are recorded in `data/sri-lanka/manifest.json` after an Actions build.
- **Attribution:** © OpenStreetMap contributors, Overture Maps Foundation. See [Attribution](../ATTRIBUTION.md) and the [Overture attribution guidance](https://docs.overturemaps.org/attribution/).

Counts in the manifest are bbox-filtered source Parquet rows before tile deduplication. They are not the number of features visible at every zoom. Missing source data is not fabricated, and this regional extraction does not imply complete POI coverage or Google Maps equivalence.

## Rendering dependencies

The map renderer is MapLibre GL JS. The PMTiles browser adapter uses HTTP range requests against the same-origin archives. MapLibre label glyphs are retrieved from the public OpenFreeMap font endpoint, which is a third-party service dependency; geographic vector data remains served from this project site.

## Refresh

Every `main` push and manual workflow dispatch resolves the latest official Overture release and rebuilds the regional archives. Review the generated manifest and Actions browser verification before treating a deployment as current. If Pages limits block publication, the generated site remains available as a short-lived Actions artifact.

## Reviewed community records

`records/` contains one editable JSON file per contributed feature. Each entry
retains sources, licenses, observation dates and attributions. The initial
community dataset is empty, deliberately avoiding invented geographic examples.
Accepted records compile into `data/community/manifest.json` and content-addressed
record/GeoJSON bundles. This is a supplemental layer, not a replacement Overture
release. See [contribution rules](../CONTRIBUTING.md) and [data licenses](../LICENSE-DATA.md).
